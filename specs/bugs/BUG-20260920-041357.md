# BUG-20260920-041357: Arch migration loses PAM integration and rejects readable PAM modules

## Summary
DeskUnlock's post-upgrade health check required the PAM shared object to be executable, while package migration removed the managed Plasma PAM block without reinstalling it.

## Reproduction
- Method: post-upgrade system verification and contract tests.
- Evidence: `syauth-health` reported a missing PAM module and Plasma Syauth PAM entry after `deskunlock` replaced `syauth-suite`; `cargo test --test packaging_contract` initially failed because no Arch install script existed and the health check used `check_exec` for the PAM module.

## Expected Behavior
A readable regular PAM shared object passes health validation, and Arch install/upgrade hooks idempotently invoke `syauth-pam-sync install` without removing the password fallback.

## Actual Behavior
The health check rejected mode `0644` `pam_syauth.so`, and the package had no install/upgrade callback to restore the managed `plasmalogin` block after rename removal.

## Root Cause Analysis
The health script applied an executable-file predicate to a shared library. The Arch package relied only on an alpm hook targeting package transactions that did not cover the rename path.

## Fix
Use a regular-file/readable check for the PAM module and add `deskunlock.install` `post_install`/`post_upgrade` callbacks that run `syauth-pam-sync install` when `plasmalogin` exists. No `post_remove` callback is added.

## Traceability
- Failing test: `tests/packaging_contract.rs`
- Fixed in: `desktop/bin/syauth-health`, `packaging/arch/PKGBUILD`, `packaging/arch/deskunlock.install`
